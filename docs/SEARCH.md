# Semantic search and Dante sources

**Search** finds related ideas in task notes, meeting notes, vault names/descriptions/URLs and lecture summaries. It does not fetch linked websites, decode vault files or index lecture audio/transcripts. Results show the matching section and open the saved source. Dante chat and Live can use the read-only `search_notes` tool to answer questions such as “what did Alex say about the launch?” with `[S1]` citations and server-generated source links. Always check the original context: similarity and AI answers are not proof that a person said something.

## Setup

1. Run the latest **entire** `supabase-schema-update.sql` after the base schema. It enables the `vector` extension, creates `embeddings`, installs source-change triggers and backfills existing searchable content as pending rows. Supabase supports pgvector; if the extension is not available, the migration warns and skips only semantic search. Enable **vector** in Supabase Database → Extensions and rerun. Do not change ownership of managed Realtime tables; see docs/REALTIME.md if that separate section warns.
2. Configure server-only `LLM_BASE_URL` and `LLM_API_KEY` for your OpenAI-compatible embedding provider. The server calls `{LLM_BASE_URL}/embeddings`; a base ending in `/chat/completions` is normalized to its parent first. Existing `LLM_EXTRA_HEADERS` are supported. This embedding endpoint is required even if chat uses Gemini. Never use `VITE_` secrets.
3. Set `EMBEDDING_MODEL` (default **Qwen3-Embedding-0.6B**) to the name exposed by your provider. Qwen's [official model table](https://github.com/QwenLM/Qwen3-Embedding#model-series) lists **1,024 embedding dimensions** for the 0.6B model (checked 2026-10-27). The table uses `vector(1024)`. Every response is checked for exactly 1,024 finite, nonzero dimensions and normalized before storage; wrong dimensions fail explicitly. The server does not silently truncate/pad vectors or request reduced dimensions. A different model must return 1,024 dimensions; changing the schema for another size requires a deliberate migration/reindex.
4. Supply the existing `SUPABASE_URL`, `SUPABASE_ANON_KEY` (or their existing VITE fallbacks) and **server-only** `SUPABASE_SERVICE_ROLE_KEY`. Searches require a verified account, even when anonymous Dante is allowed. `GET /api/search/status` reports configuration, not provider health or migration completion.
5. Restart/redeploy, open Search and try a question. Source triggers immediately queue every create/update and delete stale rows. The server worker handles one account batch every 15 seconds, including changes made while browsers are closed. The browser also debounces saved-content changes for quicker indexing, and a search processes up to 16 pending sections before ranking. **Index pending notes** processes another batch. Large backfills can take several batches/days under the quota; the page and Dante explicitly warn when sections remain pending.

The current deployment must have one background indexer per database. On extra server replicas set `SEARCH_INDEX_WORKER=false`; the default is true. Per-process locks coalesce overlapping browser/worker operations for an account. SQL revision checks reject stale writes after an edit/delete. Multiple independent API replicas can duplicate provider work/quota reservations; distributed leases/queues are not included. Provider/storage failures back off from one minute up to fifteen minutes rather than retrying every poll. Quota-exhausted accounts are deferred until midnight UTC; other accounts continue. A Pro upgrade or manual request can resume earlier through the normal server entitlement check.

## Index and isolation

`embeddings` is a derived index with `user_id`, `source_type`, `source_id`, `content`, `embedding vector(1024)`, chunk index, title, revision and model-space identity. Documents are split into 2,000-character chunks with 200-character overlap, preserving the full searchable text. Task/meeting rows without notes produce no entries. Vector rows are nullable while pending; search never uses missing vectors or those from a different provider/model space. Provider URL, model and dimensions identify a space, so changing those triggers reindexing and avoids mixing vectors. If a provider replaces weights behind the same model name/URL, rebuild by clearing that index's vectors/model through an administrator before indexing again.

Authenticated users may SELECT only their own index rows under RLS. Browser INSERT/UPDATE/DELETE and internal index RPCs are denied; trigger functions and service-role-only revision-checked writes own maintenance. Bodies cannot select an owner or send canonical cloud content/vectors. Source and search reads use the verified user's JWT/RLS; only the worker reads its explicitly scoped batches with service credentials. Database-trigger maintenance is transactional, including note clearing, deletion and ownership transfer. Account deletion cascades the index. Account exports already include the original searchable tables; derived vectors are intentionally rebuilt rather than included in exports.

A cosine HNSW index is available; the matching RPC materializes the account/model slice before exact ranking to avoid global nearest-neighbor cutoff starving small accounts. It deduplicates sections per source, applies a 0.25 minimum cosine similarity and returns up to eight sources. Ranking is semantic retrieval, not a guarantee of relevance or correctness. Source links read fresh owned data and report deleted/unavailable sources. The source preview is bounded to 500,000 characters.

## Limits and Dante

A nonempty indexing batch (up to 16 sections) or search consumes **one daily Dante message allowance** before provider work. Searching may embed one query plus that batch in one request. A clean index check, status request or source read consumes no daily allowance. Quota exhaustion returns 429/Retry-After and makes no provider call; storage/entitlement-check failure prevents provider work. Pro exemption is checked on the server. Failed or cancelled admitted attempts may consume allowance. HTTP requests retain the shared per-minute rate limit. Background indexing uses the exact same atomic daily reservation and entitlement logic.

Dante performs at most one read-only tool request per chat/Live turn. A bounded model planner selects `search_notes`; malformed planner output falls back to retrieving the current question, never to a write. Tool routing, query embeddings and up to 16 pending sections are included in that turn's existing one-message reservation, rather than charging a second message. Authenticated caller-supplied search results/local sources are ignored. Evidence enters the system prompt as bounded JSON data with instructions to cite actual sources, distinguish interpretation from quotations and admit unavailable/incomplete evidence. Source footers are built from validated retrieval rows on the server and persist in ordinary Dante message history. Retrieval turns are read-only: a trusted SSE flag makes chat/Live strip action JSON even if the model emits it. Changes require a separate follow-up. No retrieval tool is executed through client write actions, and embedded commands must not become actions.

Local/demo mode remains independent: Search performs explicitly labelled **text search** across this browser's saved data, without database, vector, embedding, indexing or quota requests. Local Dante receives up to 100 bounded local sources for text evidence under the existing anonymous-AI policy. This is not semantic retrieval; sign in to use cloud semantic search. No notes are fetched from another account on mode/account changes, and late reads are ignored.

Content is sent to your configured embedding provider when indexed; selected evidence is also sent to the chat provider for Dante answers. Do not log notes, vectors, queries, tool/model output or credentials. Embeddings can reveal information and receive the same access protection as their source notes. Live external provider/Supabase delivery requires deployment credentials; automated tests use deterministic embeddings and real embedded pgvector for ranking, RLS, migrations and stale-write checks.
